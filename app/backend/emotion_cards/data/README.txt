빈틈사이 오늘의 마음 카드 장면 연출 데이터 v2.0

런타임 흐름
사용자 입력
→ 사실 추출 LLM
→ 시간 앵커·범위 및 감정/날씨 타임라인 정규화
→ 로컬 안전 검사
→ 명시 사실 하드 제약 생성
→ CSV 후보 검색
→ 우선순위·충돌 해결
→ 장면 연출 LLM
→ 장면 JSON 결정론적 검증 및 최대 1회 repair
→ 이미지 프롬프트 컴파일
→ gpt-image-2 이미지 생성
→ 결과·후보 점수·근거·최종 프롬프트 저장

핵심 원칙
- 분석은 입력에 존재하는 사실만 추출하며 장면을 만들지 않는다.
- 여러 시점이 있으면 마지막 명시 감정을 주 감정으로 사용하고 이전 감정은 보조 감정과 환경 흔적으로 남긴다.
- 퇴근·하교·출근 같은 생활 사건은 시간 앵커와 확률적 범위로 분리하며 정확한 시각으로 단정하지 않는다.
- 집에서 나서는 길·집으로 돌아오는 길은 순서와 경로 앵커만 사용하며 다른 근거가 없으면 시간대 범위를 비워 둔다.
- 비에서 맑음으로 바뀐 경우 현재 장면은 비 갠 뒤 날씨를 사용하고 젖은 지면·물방울로 이전 날씨를 보존한다.
- energy와 need는 명시 또는 confidence 0.75 이상의 고신뢰 추론이 아니면 null이다.
- CSV 00~28은 최종 장면 정답표가 아니라 후보, 시각 단서, 제약, 우선순위, 회귀 검증 자료다.
- 사용자 명시 감정·원인·날씨·시간·장소·행동·소품·부정 표현은 가장 높은 우선순위다.
- 장면 연출 LLM은 카테고리별 상위 3~5개 후보 안에서만 ID를 선택한다.
- 결정론적 검증은 후보 ID, 하드 제약, 필수 시각 단서, 호환성, 개수 제한, 개인정보와 안전을 검사한다.
- style은 선, 질감, 셰이딩, 재료 표현과 렌더링 방식에만 영향을 주고 장면 ID를 바꾸지 않는다.
- 카드 메시지는 생성 이미지 안에 넣지 않고 UI/Canvas에서 별도 합성한다.
- 배열 값은 | 구분자를 사용하고 모든 CSV는 UTF-8-SIG로 저장한다.

주요 파일 역할
- 01, 02, 24: 사실 추출 스키마·코드·few-shot
- 03~10: 사건·날씨·장소·조명·인물·행동·소품·구도 후보 카탈로그
- 11: 렌더링 전용 스타일
- 12~16, 28: 감정·사건·에너지·필요·관심사·동행 후보 점수
- 19, 21: 안전 하드 제약과 충돌 우선순위
- 20: 단계별 결정론적 폴백
- 22, 23: 장면 연출/이미지 프롬프트 템플릿과 scene v2.1 timeline 스키마
- 25, 26: 허용 범위 회귀 테스트와 자동 생성 검증 보고서
