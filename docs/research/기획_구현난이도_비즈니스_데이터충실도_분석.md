# 기획 구현난이도·비즈니스 모델·데이터 충실도 분석

## 1. 분석 개요

본 문서는 `★ 종합 기획안 v3 (통합본) (1).md`와 `요구사항 정의서 (1).md`를 기준으로, 현재 기획의 구현 가능성·사업성·데이터 준비 상태를 검토한 문서다.

분석 대상 서비스는 **비의료 마음 웰니스 웹앱**이다. 사용자는 캐릭터와 자유롭게 대화하고, 서비스는 백엔드에서 감정·심리 신호·척도 신호를 추정한 뒤 결과카드와 위로형 응답을 제공한다. 기획의 핵심은 `대화가 곧 측정`이라는 숨은 척도 엔진이며, 사용자는 검사나 진단을 받는 느낌 없이 캐릭터와 수다를 나누는 경험을 한다.

최종 판단은 다음과 같다.

| 항목 | 판단 | 요약 |
|---|---|---|
| 구현난이도 | 중상~상 | 핵심 MVP는 가능하나, 전체 기획을 38일 내 완성형으로 구현하기는 어렵다. |
| 비즈니스 현실성 | 조건부 현실적 | `AI 상담`이 아니라 `비의료 감정 수다 + 마음카드`로 포지셔닝해야 한다. |
| 데이터 충실도 | 핵심 데이터 일부 보강 필요 | 현재 시드 데이터는 방향성이 맞지만, AIHub 원천 대화 데이터 반영이 필수다. |
| 최우선 전략 | 좁고 깊은 MVP | 기능 수를 줄이고 `대화 분석 → 맞춤 응답 → 결과카드`의 완성도를 높여야 한다. |

## 2. 서비스 핵심 플로우 기준 분석

기획서상 서비스 플로우는 다음 구조다.

```text
사용자 진입
→ 캐릭터 선택 또는 가벼운 오프너
→ 자유 대화
→ 감정 분석
→ 키워드/원인 분석
→ 6척도 관련 심리 신호 추정
→ 위험 신호 탐지
→ 캐릭터 맞춤 응답
→ 필요 시 자연스러운 앵커 질문
→ 오늘의 마음 결과카드 생성
→ 메모리 저장
→ 주간/월간 리포트 및 이너 카운슬로 확장
```

이 플로우에서 사용자가 직접 체감하는 것은 `캐릭터 대화`, `위로`, `결과카드`, `기억해주는 느낌`이다. 반대로 서비스의 차별성을 만드는 내부 기능은 `감정분석`, `척도추정`, `위험탐지`, `RAG`, `멀티에이전트 오케스트레이션`이다.

따라서 구현 판단은 단순히 채팅 UI가 가능한지로 보면 안 된다. 이 서비스가 대충 만든 챗봇처럼 보이지 않으려면, 최소한 아래 연결이 실제로 작동해야 한다.

```text
사용자 발화
→ 감정/심리 신호 구조화
→ 캐릭터 응답에 반영
→ 결과카드 문장에 근거로 반영
```

## 3. 구현난이도 분석

### 3.1 전체 난이도

| 범위 | 난이도 | 판단 |
|---|---:|---|
| 얇은 채팅 데모 | 중 | GPT API와 React/FastAPI로 빠르게 구현 가능 |
| 깊이 있는 MVP | 중상 | 감정분석, 위험탐지, 결과카드, 메모리까지 필요 |
| 기획서상 MVP 전체 | 상 | 자체 ML, 6척도 추정, 안전, RAG, 메모리, AWS 배포 포함 |
| MVP+ 및 P2 | 매우 상 | 이너 카운슬, 월간 리포트, 친밀도 성장, opener, 추천 기능까지 포함 |

현재 기획은 기능 개수가 많다. 하지만 발표·시연 기준으로는 전체 기능을 모두 구현하는 것보다, **핵심 플로우 하나를 완성도 있게 구현하는 전략**이 적합하다.

### 3.2 기능별 구현난이도

| 기능 | 요구사항 | 난이도 | 분석 |
|---|---|---:|---|
| 캐릭터 대화 | FR-01 | 중 | 캐릭터별 시스템 프롬프트와 말투 차별화로 구현 가능하다. 다만 5턴 이상 맥락 유지가 필요하다. |
| 감정 분석 | FR-02 | 중상 | KcELECTRA 파인튜닝까지 하면 난이도가 오른다. 발표용 MVP에서는 `LLM 분류 + 룰 기반 + 추후 ML 모델` 구조가 현실적이다. |
| 형태소 분석 | FR-03 | 중 | KoNLPy는 환경 세팅 이슈가 있을 수 있다. Kiwi 등 대체 분석기도 검토 가능하다. |
| 척도 추정 | FR-04 | 상 | 6척도 문항을 대화 근거로 추정해야 하므로 과신·오탐 위험이 크다. 점수 노출보다 내부 신호화가 적절하다. |
| 앵커 문항 삽입 | FR-05 | 중상 | 자연스럽게 질문해야 한다. 대화 흐름을 깨지 않는 질문 템플릿과 삽입 조건이 필요하다. |
| 일일 결과카드 | FR-06 | 중 | LLM 요약과 카드 템플릿으로 구현 가능하다. 핵심은 대화 근거와 카드 문장이 연결되어야 한다는 점이다. |
| 주간/월간 결과카드 | FR-07 | 중상 | 누적 DB와 시계열 요약이 필요하다. MVP 이후가 적절하다. |
| 상태별 결과카드 | FR-08 | 중상 | 번아웃, 사기꾼증후군 등 상태별 RAG 지식과 안전 문구가 필요하다. |
| 내 마음 설명서 | FR-09 | 상 | 개인화 결과 상품으로 가치가 있지만 데이터 누적이 전제된다. P2가 적절하다. |
| 메모리 | FR-10 | 중상 | 단순 로그 저장이 아니라 사용자 요약 프로필, 최근 이슈, 선호 위로 방식 분리가 필요하다. |
| 친밀도 성장 | FR-11 | 중 | 규칙 기반으로 시작 가능하다. 핵심 MVP에는 필수는 아니다. |
| 이너 카운슬 회의 | FR-12 | 상 | 멀티에이전트 차별화에 좋지만 품질 관리가 어렵다. MVP+ 시연 기능으로 두는 것이 적절하다. |
| opener | FR-13 | 중 | 운세·날씨·MBTI 기반 첫 인사는 구현 가능하나 핵심 기능은 아니다. |
| 안전·위기 대응 | FR-14 | 상 | 기술보다 책임이 어렵다. recall 우선 룰, 고위험 결제 OFF, 전문기관 안내가 필수다. |
| 음악·활동 추천 | FR-15 | 중 | 상태 기반 추천은 가능하나 차별화 핵심은 아니다. P2가 적절하다. |

### 3.3 가장 어려운 기술 지점

#### 3.3.1 대화 기반 척도 추정

요구사항은 `PHQ-9`, `GAD-7`, `PHQ-15`, `RSES`, `UCLA-3`, `SPANE` 6척도를 대화 근거로 추정하는 것이다. 이 기능은 서비스의 핵심 차별점이지만 동시에 가장 위험한 기능이다.

문제는 사용자의 일상 표현이 척도 문항과 1:1로 대응되지 않는다는 점이다.

```text
사용자: 요즘 아무것도 하기 싫어.

가능한 해석:
- 우울 관련 흥미 저하
- 번아웃
- 일시적 피로
- 수면 부족
- 회피성 스트레스
```

따라서 MVP에서는 정식 점수처럼 보이게 하면 안 된다. 내부적으로는 문항별 신호를 추정하되, 사용자에게는 다음처럼 표현해야 한다.

```text
부적절: PHQ-9 추정 14점입니다.
적절: 오늘 대화에서는 의욕 저하와 피로 신호가 함께 보여요.
```

#### 3.3.2 감정분석과 캐릭터 응답 연결

단순히 감정 라벨만 뽑는 것은 충분하지 않다. 대충 만든 서비스처럼 보이지 않으려면 분석 결과가 캐릭터 응답에 반영되어야 한다.

예시:

```text
분석 결과:
- 주감정: 불안
- 보조감정: 자기비난
- 원인: 취업 압박
- 위험도: 일반
- 필요한 응답: 안심 + 감정정리 + 작은 실행

캐릭터 응답:
지금 네가 약해서 불안한 게 아니라, 결과를 계속 의식하면서 긴장 상태가 오래 이어진 것 같아.
오늘은 해결책부터 찾기보다, 제일 크게 걱정되는 장면 하나만 같이 꺼내보자.
```

#### 3.3.3 안전·위기 대응

위험 신호 탐지는 서비스 신뢰와 직결된다. 자해·자살·폭력 피해·극단적 무망감 표현을 놓치면 안 된다. 요구사항의 `recall ≥ 0.9`는 적절하지만, 구현 부담은 높다.

MVP에서는 다음 구조가 현실적이다.

```text
1차: 위험 키워드/패턴 룰 기반 탐지
2차: LLM 위험도 분류
3차: 고위험이면 일반 응답 중단
4차: 전문기관 안내 + 결제 OFF
5차: 로그에 safety_flag 저장
```

### 3.4 현실적인 구현 범위 제안

38일 프로젝트 기준으로 깊이 있는 MVP는 아래 범위가 적절하다.

| 구분 | 포함 | 제외 또는 후순위 |
|---|---|---|
| 대화 | 캐릭터 3종, 5~10턴 맥락 유지 | 캐릭터 성장 애니메이션 |
| 분석 | 감정·강도·원인·심리신호 추정 | 모든 감정/척도에 대한 완전 자동 점수화 |
| 척도 | 6척도 기반 신호 매핑 | 사용자에게 점수 직접 노출 |
| 안전 | 자해·자살·고위험 표현 탐지 | 전문상담 서비스 직접 연결 자동화 |
| 결과 | 오늘의 마음 카드 | 월간 리포트 전체 |
| 메모리 | 직전 세션 요약 기억 | 장기 성향 모델링 |
| 멀티에이전트 | 내부 모듈 분리, 간단한 이너 카운슬 시연 | 완전 자동 다중 에이전트 토론 고도화 |
| BM | 무료 대화 + 카드 맛보기 | 실제 결제 시스템 |

### 3.5 구현난이도 결론

현재 기획은 구현 자체가 불가능한 것은 아니다. 다만 **모든 기능을 얕게 구현하면 경쟁력이 없어지고, 핵심 기능을 깊게 구현해야 설득력**이 생긴다.

권장 MVP는 다음 한 문장으로 정의할 수 있다.

```text
사용자가 캐릭터와 5~10턴 대화하면, 시스템이 감정·원인·심리신호를 분석하고, 그 근거가 반영된 맞춤 위로와 오늘의 마음 결과카드를 제공한다.
```

## 4. 비즈니스 모델 분석

### 4.1 비즈니스 가설

기획서의 비즈니스 가설은 다음과 같다.

```text
대화는 무료로 제공하고,
개인화된 결과카드·리포트·내 마음 설명서에 과금한다.
```

이 방향은 타당하다. 사용자는 일반적인 챗봇 대화에는 비용 지불 의향이 낮을 수 있지만, `나에 대한 해석`, `공유 가능한 결과물`, `누적 변화 리포트`에는 상대적으로 돈을 낼 가능성이 있다.

즉 이 서비스의 상품은 챗봇 자체가 아니라 **대화에서 추출한 자기이해 콘텐츠**다.

### 4.2 수익모델별 현실성

| 수익모델 | 현실성 | 분석 |
|---|---:|---|
| 캐릭터 대화 유료화 | 낮음 | Character.AI, ChatGPT 등 대체재가 많다. 무료 진입이 필요하다. |
| 일일 결과카드 무료 + 공유 | 높음 | 바이럴 유입과 첫 경험 형성에 적합하다. |
| 상태별 결과카드 건별 결제 | 중상 | 번아웃, 자존감, 관계 피로 등 사용자가 공감하는 주제라면 결제 가능성이 있다. |
| 주간/월간 리포트 구독 | 중 | 리텐션이 검증된 뒤 가능하다. 초기부터 구독은 부담이 크다. |
| 내 마음 설명서 유료 상품 | 중상 | 공유용 PDF/카드 형태라면 심리테스트·운세 결제와 유사한 지불 동기가 있다. |
| 위로 선물하기 | 중 | 감성적 바이럴은 가능하지만 실제 결제 검증이 필요하다. |
| 기업·대학 B2B2C | 중장기 | 신뢰성과 안전·개인정보 체계가 갖춰진 뒤 가능하다. |

초기에는 구독보다 건별 결제가 더 현실적이다.

```text
추천 초기 BM:
- 캐릭터 대화: 무료
- 오늘의 마음 카드: 무료
- 상태별 결과카드: 저가 건별 결제
- 주간 리포트: 저가 건별 결제 또는 크레딧
- 내 마음 설명서: 프리미엄 단품
```

### 4.3 고객 지불 이유

사용자가 돈을 내는 이유는 `AI가 대답해줘서`가 아니라 다음 가치 때문이다.

| 지불 가치 | 설명 |
|---|---|
| 자기이해 | 내 감정과 반복 패턴을 정리해준다. |
| 위로의 개인화 | 일반 위로 문구가 아니라 내 말에 근거한 위로를 받는다. |
| 공유성 | 결과카드가 친구·연인·SNS에 공유 가능한 형태다. |
| 누적 가치 | 계속 사용할수록 주간·월간 흐름이 생긴다. |
| 낮은 문턱 | 상담이나 검사보다 가볍고 익명성이 높다. |

### 4.4 시장 포지셔닝 현실성

이 서비스는 `AI 심리상담`으로 포지셔닝하면 위험하다. 의료·상담 책임과 정서 의존 문제가 커진다. 반대로 `감정 수다 기반 자기이해 콘텐츠`로 포지셔닝하면 현실성이 높아진다.

| 위험한 포지션 | 권장 포지션 |
|---|---|
| AI 심리상담 서비스 | 비의료 감정 웰니스 서비스 |
| 우울·불안 진단 서비스 | 대화 기반 마음 체크인 |
| 치료 효과 제공 | 위로·자기이해·회복 도움 |
| 심리검사 자동 채점 | 대화에서 보이는 마음 신호 정리 |

문구도 다음처럼 관리해야 한다.

```text
부적절:
- 우울증을 진단합니다.
- 불안장애 여부를 알려드립니다.
- AI가 치료해드립니다.

적절:
- 오늘 대화에서 보인 마음 신호를 정리해드려요.
- 진단이 아닌 자기이해용 마음 카드입니다.
- 힘든 마음을 캐릭터와 함께 안전하게 정리해보세요.
```

### 4.5 핵심 사업 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| 의료기기·상담 오인 | 매우 큼 | 진단·치료·효능 표현 금지, 점수 직접 노출 제한 |
| 위기 대응 실패 | 매우 큼 | 룰+LLM 이중 탐지, 고위험 결제 OFF, 전문기관 안내 |
| GPT 비용 증가 | 큼 | 모델 분리, 캐싱, 요약 메모리, 저가 모델 병행 |
| 리텐션 부족 | 큼 | 메모리, 주간 리포트, 캐릭터 관계성, 결과카드 연속성 강화 |
| 차별화 약화 | 중 | 단순 챗봇이 아니라 결과카드와 숨은 척도 엔진을 전면화 |
| 개인정보·민감정보 부담 | 큼 | 동의, 암호화, 원문 최소 저장, 요약 메모리 중심 설계 |

### 4.6 비즈니스 모델 결론

비즈니스적으로 완전히 비현실적인 기획은 아니다. 오히려 `캐릭터챗`, `심리테스트`, `운세형 결과카드`, `멘탈 웰니스`의 접점에 있어 초기 유입 가능성은 있다.

다만 성공 조건은 명확하다.

```text
1. AI 상담이 아니라 비의료 감정 웰니스로 포지셔닝한다.
2. 대화 자체가 아니라 결과카드와 자기이해 리포트에 과금한다.
3. 위험 신호 대응과 결제 OFF를 제품 신뢰 요소로 만든다.
4. 캐릭터 수다의 재미와 척도 기반 해석의 신뢰를 동시에 보여준다.
5. 초기에는 구독보다 저가 단품 결제로 검증한다.
```

```text
AI허브 감성 대화 말뭉치: 다운·전처리 완료
```

현재 데이터 폴더 기준:

```text
AI허브 감성 대화 말뭉치: 미확보로 catalog에 표기
AI허브 웰니스 대화 스크립트: 미확보로 catalog에 표기
```

따라서 산출물 일관성을 위해 둘 중 하나가 필요하다.

```text
1. 실제 원천/라벨 파일은 `storage/datasets/raw/`에 보관하고, 모델/RAG용 정제 산출물은 `storage/datasets/processed/flagship/`에 생성한다.
2. 아직 미확보라면 기획서의 "다운 완료" 표현을 "확보 예정/신청 필요"로 수정한다.
```

그 다음으로 아래 2개를 보조 반영하면 좋다.

## 7. 최종 결론

현재 기획은 비즈니스적으로 가능성이 있고, 구현도 불가능하지 않다. 하지만 성공 조건은 명확하다.

```text
기능을 많이 넣는 것보다
대화 분석 → 맞춤 응답 → 결과카드의 연결을 깊게 구현해야 한다.
```

기획서의 전체 범위를 모두 구현하면 난이도는 매우 높다. 그러나 범위를 `감정 맞춤 캐릭터 대화 + 숨은 척도 신호 + 결과카드`로 압축하면, 38일 프로젝트에서도 충분히 설득력 있는 결과물을 만들 수 있다.

최종적으로 이 서비스는 다음 기준을 만족해야 한다.

```text
1. 사용자는 검사받는 느낌 없이 대화한다.
2. 백엔드는 감정·심리 신호를 구조화한다.
3. 캐릭터 응답은 분석 결과를 반영한다.
4. 결과카드는 대화 근거가 있는 개인화 콘텐츠다.
5. 위험 신호는 최우선으로 감지하고 결제보다 안전을 앞세운다.
```

이 다섯 가지가 구현되면, 현재 기획은 `대충 만든 챗봇`이 아니라 **개인 맞춤형 마음 웰니스 플랫폼의 MVP**로 평가받을 수 있다.
