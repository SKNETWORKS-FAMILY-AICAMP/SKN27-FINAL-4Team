# 감정분류 개선 실험 계획서

## 1. 현재 상태 (1차 · 완료)

| 항목 | 내용 |
|---|---|
| 데이터 | AI Hub 감성대화 정제본 58,234건 (계보 100% 검증 — EDA §0-2) |
| 방식 | KcELECTRA-base-v2022 **얼려쓰기**(frozen 임베딩) + XGBoost |
| 성능 | **Acc 65.8% / Macro F1 0.670** (test 11,647건) |
| 서비스 반영 | 감정 라벨은 화면 비노출, 응답 톤 결정에만 사용 · 3단 폴백(모델→LLM→normal) |

## 2. 한계와 3겹 보완 전략

| 겹 | 한계 | 보완 | 상태 |
|---|---|---|---|
| ① 설계 | 오분류 시 잘못된 톤 위험 | 라벨 비노출 + "무조건 편들기" 공통 태도 → 인접 감정 오분류의 체감 비용 낮음 | ✅ 반영됨 |
| ② 추론 | 문맥 없는 단문 오분류 (실측: "점심에 김치찌개 먹었어" → anger) | **확신도 게이트**: 모델 확신 <0.55면 최근 대화를 아는 LLM으로 재분류 + **초단문 바이패스**: 10자 미만은 직전 감정 유지 | ✅ 구현·실측 검증 (2026-07-03: "김치찌개"→normal, "몰라…"→직전 슬픔 유지, "합격!!"→joy 전환) |
| ③ 운영 | 학습(2020 작성체) ↔ 실사용(2026 채팅체) 드리프트 | 월간 라벨 분포 비교 · 폴백 발동률 추적 · 저확신 샘플 수집 → 재학습 루프 | 📋 운영 후 |

## 3. 실험 ① — 모델 × 사용 방식 (4조합)

> 개념 정리: "어떤 뇌를 쓸까"(모델)와 "그 뇌를 어떻게 쓸까"(방식)는 별개의 축.
> 얼려쓰기 = 문장→숫자 변환만 시키고 XGBoost가 판단 / 파인튜닝 = 모델 자체를 감정 데이터로 학습.

| | 얼려쓰기 + XGBoost | 파인튜닝 |
|---|---|---|
| **KcELECTRA-base-v2022** | ✅ 65.8% (기준선) | 실험 A |
| **KoBERT** | 실험 B | 실험 C |

- **가설**: KcELECTRA 우세 — 댓글(반말·구어체) 사전학습 모델이고, 우리 데이터는 존댓말 0.1%의 구어체(EDA §9-6). KoBERT는 위키·뉴스(문어체) 기반.
- **기대 효과**: 파인튜닝 전환 시 통상 +5~10%p → 70%대 중반 목표.
- **평가 규칙**: 동일 분할(병합 후 8:2, seed 고정) · Macro F1 우선(클래스 불균형 2.8배 고려) · 환경 Colab GPU.

## 4. 실험 ② — 데이터셋 추가 (승자 조합 기준 ablation)

> 원칙: "추가하면 잘될 것"이라 가정하지 않는다. **실험으로 확인하고, 오르는 것만 채택.**
> (라벨 체계·문체가 다르면 오히려 하락 가능)

| 조합 | 데이터 | 확보 상태 | 유의점 |
|---|---|---|---|
| 기준선 | 감성대화 58,234 | ✅ | — |
| +웰니스 | AI Hub 웰니스 대화 스크립트 | ✅ 보유 | 상담 의도 라벨 → 4모드 매핑 규칙 필요 |
| +음성전사 | AI Hub 감정 대화 음성 (텍스트 전사) | ✅ 보유 | 7감정 → 4모드 매핑 |
| +KOTE | 한국어 온라인 댓글 5만 건 (44감정) | 공개 다운로드 | 44 → 4모드 매핑 · 라이선스 공개형 |

- **주의**: 현 데이터는 전부 크라우드 작성체 — 같은 스타일 추가는 한계 효용 체감. 장기적으로 가장 값진 추가 데이터는 **실사용 채팅 로그 라벨링**(§2-③ 루프와 연결).
