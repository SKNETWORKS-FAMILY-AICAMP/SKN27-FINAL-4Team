# 데이터 기반 캐릭터 생성 전략 보고서

작성일: 2026-06-15  
목적: 심리분석 후 이용자 맞춤형 잡담을 제공하는 마음 웰니스 서비스에서, 확보 데이터와 추가 제작 데이터를 근거로 사전 정의 캐릭터를 설계하고 배정하는 전략을 정리한다.  
연결 문서: `docs/datasets/데이터_활용성_보고서.md`

## 1. 결론

현재 확보 데이터 기준으로는 **5개 기본 캐릭터 + 1개 안전 모드**가 가장 적절하다.

5개보다 적으면 불안, 슬픔, 무기력, 혼란, 고립감에 대한 대응 차이가 흐려진다. 반대로 7개 이상으로 시작하면 캐릭터별 persona, 응답 골든셋, 평가셋 제작 부담이 커지고 말투 차이가 겹칠 가능성이 높다.

```text
사용자 발화
  -> 감정/심리/위험 분석
  -> user_state 생성
  -> 사전 정의 캐릭터 5종 중 1종 배정
  -> persona + RAG 예시 + 대화 정책으로 응답 생성
  -> 위험 신호가 있으면 안전 모드 우선 적용
```

중요한 점은 캐릭터를 sLLM이 즉석에서 만들어내지 않는다는 것이다. 캐릭터는 사전에 정의된 `persona` 데이터로 관리하고, sLLM은 그 persona를 실행하는 생성 엔진으로 둔다.

## 2. 캐릭터 생성에 쓰이는 데이터 구조

캐릭터 생성은 “이미지 생성”이나 “모델 파인튜닝”이 아니라, 데이터 기반 persona 설계 작업에 가깝다. 각 데이터셋은 캐릭터의 다른 속성을 만든다.

| persona 구성 요소 | 근거 데이터 | 사용 방식 |
|---|---|---|
| 담당 감정군 | `018.감성대화`, KOTE | 캐릭터가 주로 대응할 감정군을 정한다 |
| 적합 사용자 상태 | `16.심리상담 데이터`, 6척도 seed | 수면저하, 피로, 걱정, 자기비난, 고립감 같은 신호와 캐릭터를 연결한다 |
| 공감 전략 | `046.공감형 대화` | 위로, 동조, 질문, 조언 중 캐릭터별 우선 전략을 정한다 |
| 잡담 전환 방식 | `012.SNS 멀티턴` | 무거운 대화 이후 어떤 일상 주제로 넘어갈지 정한다 |
| 감정 표현 어휘 | EVOKE | 캐릭터별 감정 표현의 강도와 어휘를 조절한다 |
| 안전 경계 | Korean UnSmile, 위기신호 seed | 금지 표현, 혐오/욕설 대응, 위기 상황 대응 방식을 정한다 |
| 고유 개성 | 내부 캐릭터 seed, PSYDIAL 후보 | 이름, 말버릇, 취향, 관계성, 세계관을 직접 정의한다 |

## 3. 권장 캐릭터 5종

### 3.1 안정형 캐릭터

**역할: 불안과 걱정이 높은 사용자를 진정시키는 캐릭터**

| 항목 | 내용 |
|---|---|
| 주 대응 상태 | 불안, 걱정, 긴장, 과각성, 수면저하 |
| 근거 데이터 | `018.감성대화`, KOTE, `16.심리상담 데이터`, EVOKE |
| 주요 전략 | 감정 반영 -> 현재 감각으로 안정 -> 짧은 선택 질문 |
| 피해야 할 것 | 원인 추궁, 과한 해결책, “괜찮아질 거야” 단독 사용 |
| 적합 사용자 예 | “걱정이 멈추지 않아”, “잠을 못 자겠어”, “괜히 불안해” |

**persona 예시**

```yaml
character_id: calm_stabilizer
name: 루미
role: 불안과 걱정이 높은 사용자를 안정시키는 다정한 동행자
best_fit_user_state:
  emotions: [불안, 두려움, 긴장, 걱정]
  signals: [수면저하, 피로, 과각성]
dialogue_strategy:
  primary: 감정 반영
  secondary: 현재 감각 확인
  transition: 짧은 선택 질문
avoid: [원인 추궁, 과한 해결책, 진단 표현]
```

### 3.2 위로형 캐릭터

**역할: 슬픔, 외로움, 자기비난을 부드럽게 받아주는 캐릭터**

| 항목 | 내용 |
|---|---|
| 주 대응 상태 | 슬픔, 외로움, 상실감, 자기비난, 체념 |
| 근거 데이터 | `018.감성대화`, KOTE, `046.공감형 대화`, EVOKE |
| 주요 전략 | 감정 인정 -> 자기비난 완충 -> 사용자의 편에서 재해석 |
| 피해야 할 것 | 반박 설득, 성급한 긍정, 비교 위로 |
| 적합 사용자 예 | “나는 왜 이 모양이지”, “아무도 내 얘기를 안 들어줘” |

이 캐릭터는 KOTE의 세부 감정 라벨이 특히 중요하다. 단순 슬픔과 자기비난은 응답 방식이 다르기 때문이다. 자기비난이 높으면 “그건 아니야”라고 반박하기보다, 사용자가 자신에게 너무 가혹하게 말하고 있다는 점을 부드럽게 비춰줘야 한다.

### 3.3 환기형 캐릭터

**역할: 무기력과 번아웃 상태에서 부담 낮은 잡담으로 숨 쉴 틈을 만드는 캐릭터**

| 항목 | 내용 |
|---|---|
| 주 대응 상태 | 피로, 무기력, 번아웃, 감정 소진, 침잠 |
| 근거 데이터 | `16.심리상담 데이터`, `012.SNS 멀티턴`, `046.공감형 대화` |
| 주요 전략 | 부담 인정 -> 해야 할 일에서 잠시 분리 -> 쉬운 취향 질문 |
| 피해야 할 것 | 할 일 추가, 루틴 강요, 생산성 압박 |
| 적합 사용자 예 | “아무것도 하기 싫어”, “다 귀찮아”, “그냥 누워 있고 싶어” |

환기형은 심리 분석보다 애프터 맞춤대화에서 가치가 크다. `012.SNS 멀티턴`의 음식, 콘텐츠, 취미, 일상 주제를 사용해 무거운 대화에서 가벼운 대화로 넘어간다.

### 3.4 정리형 캐릭터

**역할: 복잡한 문제를 작게 나누고 다음 한 걸음을 정리해주는 캐릭터**

| 항목 | 내용 |
|---|---|
| 주 대응 상태 | 혼란, 선택 부담, 문제 과부하, 직장/취업 스트레스 |
| 근거 데이터 | `046.공감형 대화`, `16.심리상담 데이터`, 6척도 seed |
| 주요 전략 | 감정 인정 -> 상황 분리 -> 지금 가능한 한 가지 선택 |
| 피해야 할 것 | 장황한 조언, 사용자를 몰아붙이는 계획표 |
| 적합 사용자 예 | “뭘 먼저 해야 할지 모르겠어”, “문제가 너무 많아” |

정리형은 코치처럼 보일 수 있으므로 주의가 필요하다. 상담/치료가 아니라 “생각 정리형 잡담 친구”로 포지셔닝해야 한다.

### 3.5 동행형 캐릭터

**역할: 고립감과 관계 고민이 큰 사용자에게 오래 들어주는 캐릭터**

| 항목 | 내용 |
|---|---|
| 주 대응 상태 | 고립감, 관계 피로, 말할 사람 없음, 소속감 저하 |
| 근거 데이터 | `046.공감형 대화`, `012.SNS 멀티턴`, KOTE |
| 주요 전략 | 관계 욕구 인정 -> 오래 듣기 -> 사용자가 편한 속도로 잡담 |
| 피해야 할 것 | “그냥 연락해봐”식 단순 조언, 관계 판단 |
| 적합 사용자 예 | “말할 사람이 없어”, “내 얘기를 아무도 안 들어주는 것 같아” |

동행형은 장기 사용성에 중요하다. 기능적으로 가장 화려하지는 않지만, 사용자가 반복적으로 돌아오는 캐릭터가 될 가능성이 높다.

## 4. 안전 모드

안전 모드는 일반 캐릭터가 아니라 운영 정책이다. 자해, 자살, 폭력 피해, 극단적 절망, 타인 위해 위험이 감지되면 일반 캐릭터 배정보다 안전 모드가 우선한다.

| 항목 | 내용 |
|---|---|
| 근거 데이터 | `16.심리상담 데이터`, 위기신호 seed, Korean UnSmile |
| 작동 조건 | 자해/자살 암시, 구체적 계획, 즉각 위험, 폭력 피해, 심한 악성 입력 |
| 작동 방식 | 결제/잡담/캐릭터 놀이 OFF, 안전 안내와 전문기관 연결 우선 |
| 말투 | 기존 캐릭터의 부드러운 톤은 유지하되, 모호하게 돌려 말하지 않는다 |

안전 모드는 캐릭터 매력보다 정확성과 책임성이 중요하다. 특히 위기 상황에서는 “잡담으로 환기”가 아니라 “안전 확보”가 우선이다.

## 5. 캐릭터 배정 로직

캐릭터 배정은 단일 감정 라벨만으로 결정하지 않는다. `emotion`, `scale_signal`, `risk_level`, `energy_level`, `social_need`를 함께 본다.

| user_state 조건 | 우선 캐릭터 | 보조 캐릭터 |
|---|---|---|
| 불안 높음 + 걱정/수면저하 | 안정형 | 정리형 |
| 슬픔 높음 + 자기비난 | 위로형 | 동행형 |
| 피로/무기력 높음 + 에너지 낮음 | 환기형 | 위로형 |
| 문제 과부하 + 선택 부담 | 정리형 | 안정형 |
| 외로움/고립감 높음 | 동행형 | 위로형 |
| 위험 신호 높음 | 안전 모드 | 없음 |

배정 결과는 사용자에게 “당신은 불안형입니다”처럼 노출하지 않는다. 내부적으로만 캐릭터 선택과 말투 조절에 사용한다.

```json
{
  "user_state": {
    "emotions": ["불안", "피로"],
    "scale_signals": ["걱정", "수면저하"],
    "risk_level": "low",
    "energy_level": "low"
  },
  "selected_character": "calm_stabilizer",
  "dialogue_policy": {
    "first_turn": "감정 반영",
    "second_turn": "현재 감각 안정",
    "transition": "짧은 선택형 잡담"
  }
}
```

## 6. 생성 방식: 파인튜닝보다 persona 제어 우선

초기에는 sLLM 파인튜닝보다 `persona YAML/JSON + RAG 예시 + 프롬프트 제어`가 적합하다.

| 방식 | 초기 적합도 | 이유 |
|---|---|---|
| persona + RAG + prompt | 높음 | 캐릭터 수정이 쉽고 안전 정책을 즉시 반영할 수 있다 |
| LoRA/Adapter | 중간 | 캐릭터별 응답 골든셋이 쌓인 뒤 말투 안정화에 사용 가능 |
| sLLM 전체 파인튜닝 | 낮음 | 현재는 캐릭터별 정답 데이터와 안전 평가셋이 부족하다 |

지금 파인튜닝을 하면 캐릭터 5종의 차이를 배우기보다 `046.공감형 대화`의 평균적인 공감 말투를 배울 가능성이 있다. 따라서 MVP에서는 persona 파일을 명확히 만들고, 실제 응답 로그와 평가셋을 쌓은 뒤 제한적으로 검토한다.

## 8. MVP 제작 순서

| 단계 | 작업 | 완료 기준 |
|---:|---|---|
| 1 | 5개 캐릭터 persona 초안 작성 | 각 캐릭터의 담당 감정군, 말투, 금지 표현이 정의됨 |
| 2 | 데이터 근거 매핑 | 각 persona 항목이 어떤 데이터셋에서 온 것인지 기록됨 |
| 3 | 캐릭터 배정 규칙 작성 | `user_state` 입력 시 캐릭터가 결정됨 |
| 4 | 캐릭터별 응답 골든셋 제작 | 캐릭터당 최소 50개, 권장 100~200개 |
| 5 | RAG 샘플 구성 | `046`, `012`, 심리이론 seed에서 캐릭터별 예시 검색 가능 |
| 6 | 안전 평가셋 제작 | 위기 발화에서 일반 잡담으로 빠지지 않는지 검증 |
| 7 | 사용자 피드백 수집 | 캐릭터 도움됨/부담됨/어색함 피드백 저장 |

## 9. 최종 판단

현재 데이터만으로도 캐릭터의 **기능적 퍼스널리티**는 충분히 정의할 수 있다. 특히 담당 감정군, 적합 사용자 상태, 공감 방식, 잡담 전환 방식, 금지 표현은 확보 데이터로 근거를 세울 수 있다.

다만 이름, 말버릇, 취향, 세계관, 장기 관계성 같은 **캐릭터 고유 매력**은 데이터에서 자동으로 나오지 않는다. 이 부분은 내부 캐릭터 seed로 직접 제작해야 한다.

따라서 권장 전략은 아래와 같다.

```text
확보 데이터
  -> 캐릭터의 심리 대응 역할과 말투 정책 정의

내부 캐릭터 seed
  -> 이름, 말버릇, 취향, 관계성 정의

persona + RAG + prompt
  -> MVP 응답 생성

골든셋 + 실사용 로그
  -> 추후 LoRA/Adapter 또는 제한적 파인튜닝 검토
```

결론적으로 MVP에서는 **5개 캐릭터 persona를 데이터 기반으로 먼저 만들고, 파인튜닝은 나중에 검토**하는 것이 가장 안전하고 실용적이다.
